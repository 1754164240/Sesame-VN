# 新版保护地巡护设计

用户确认：自动兑换步数、完成任务、摇骰子，保护地所有动物全部满级后自动切换。

复用森林 userPatrol 开关，以独立 ForestPatrol 执行新版流程，不再调用旧版巡护接口。独立模块方便用抓包响应验证整个请求顺序，直接改写旧节点循环会混淆两套协议，因此采用独立模块方案。

接口依据为 serve-debug/webhook.db：进入、触发首页道具、任务列表、完成任务、领取奖励、摇骰子、事件确认、地图列表、切换保护地。每次请求生成唯一标识；领奖后重新查询实际骰子次数，不根据 incAwardCount 推算。步数任务仅在服务端 FINISHED 时领取，不伪造步数；浏览任务按任务返回的耗时完成，再复查状态后领奖。

满级要求：检查 currentRegionMapList 中具有动物列表的所有地图，每只动物 level >= maxLevel 且 maxLevel > 0。空列表、缺失等级不能作为完成依据；PREPARING 地图没有动物时不阻止已开放内容完成。未开放但已返回动物的地图仍计入，避免仅完成当前地图就提前切换。抓包未提供手动切换同一保护地地图的接口，不臆造接口，若服务器不自动进入下一地图则记录状态并停止。

从 AVAILABLE 的其他保护地依次查找未满级目标；每轮记住已满级地区，避免来回切换。按用户后续要求，事件确认失败、确认异常或缺少事件编号时记录后仍继续摇骰；先重新查询实际次数，不重试确认也不伪报动物获取成功。其他接口失败、次数耗尽或达到请求上限则停止。不开启其他开关，不自动兑换需要能量或付费的任务。

保留旧 RPC 方法以免影响其他调用，本次只替换旧巡护入口。文件 UTF-8 无 BOM，注释中文，不提交、不推送；本地测试不能替代支付宝真机验证。
